# WonderLab 初始正式库 0.0.1

本基线包含现有 41 个原生 class 产品包，不包含 planned 产品，不扩大主控支持范围。产品版本、库配置版本与配套软件的内置身份统一为 `0.0.1`。目录登记不表示 GitHub 资源已经上传或硬件已验收。

## 发行文件

- 唯一仓库：`hiwonderk12/scratch-product-extensions`，源码分支 `wonderlab`。
- Release tag：`wonderlab-library-v0.0.1`。
- 根 `catalog.json` 为 `formatVersion: 3`，登记 41 个产品。
- 每个 `products/<分类>/<产品>/catalog.json` 为 `formatVersion: 2`，登记该产品的初始版本及 Release 资产地址。
- 上传的是 41 个 `<产品id>-0.0.1.zip` 单包，不是源码 ZIP，也不是包含多个包的总 ZIP。
- 本地待上传文件放在忽略的 `dist/release-assets/wonderlab-library-v0.0.1/`，不提交二进制产物。

## 人工上传顺序

1. 审阅并本地提交公开库的作者源码、正式根及所有产品历史，暂不更新远端 `wonderlab` 正式入口。
2. 在已审阅提交上创建并推送 `wonderlab-library-v0.0.1` tag（只推该 tag），在 GitHub 基于它创建 Release，上传所列 41 个 ZIP；名称必须与各产品 `asset` 完全一致。GitHub 自动生成的源码附件不能替代它们。
3. 确认 Release 已公开、ZIP 可匿名访问后，再推送 `wonderlab` 分支，使根与所有产品 JSON 一起生效。正式目录只应在资源齐备后供用户使用；不能仅推送目录就宣称发布完成。
4. 用支持分层目录的配套 WonderLab 检查版本。普通使用不勾选候选、不填写测试地址；主控与模块页面只反馈检查结果，点击卡片版本数字查看可滚动列表，选择一项后查看详情和操作。
5. 检查下载不改变当前作品、确认后才使用版本、四语、保存重开及断网固定版本恢复。全库硬件、安装包和实际 UI 仍需分别验收。

若公开库和资源都尚未上传，请先准备 Release 资产，资源可下载后再公布目录入口。工具不会自动上传、创建远端 tag 或发布。

## 旧数据与后续版本

本基线移除仓库中的调试发行目录和说明，不删除用户本机安装资源，也不改写旧工程版本锁。删除远端实验 Release 后，尚未安装的实验版本可能无法恢复；请先备份仍需使用的准确版本 ZIP。缺失版本应明确报错，不能静默换用 `0.0.1`。

旧客户端若只认识平铺 v2，不能读取新的 v3 正式根；须升级到支持分层目录的配套软件。当前没有已经确认的最低公开安装版，开发环境人工验证不等于所有旧安装版可用。

之后正常发行遵循[不可变版本与产品历史合同](../native-catalog.md#按产品维护-catalogjson)：修改已发行内容须递增产品版本并追加历史；不要重复将未来发行归零或覆盖同版 ZIP。仅当库配置变化时才协调新的库快照和配套版本。
