# WonderLab 原生积木库 0.1.11 基线

## 如何使用

正式集合 tag 为 `wonderlab-library-v0.1.11`，包含现有 41 个原生 class 产品包，不包含 4 个 planned 占位模块。
每个产品保留自己的版本号；集合 tag 不是所有产品共同的版本号。
全部包携带一致的 `0.1.11` 库配置快照，主控支持范围没有扩大。

在支持原生 class 包及 formatVersion 2 目录的 WonderLab 中，打开“用户拓展”，使用正常“检查版本”入口。
默认读取本仓库 `wonderlab` 分支根 `catalog.json`，无需连接测试目录或允许候选包。
先选择适配主控，再下载、明确加载对应模块。安装新版本不自动升级当前工程，保存的工程继续按版本锁恢复。

此库基线不等于已发布新的 WonderLab 安装包。旧软件可能没有相应加载能力，不能仅凭“14.1.2”等显示版本判断兼容。
配套软件应使用包含本轮目录修复的构建，以安装包旁 `SOURCE-PAIR.json` 的软件完整提交号识别；最低正式软件版本尚未确认。
联调安装包仍使用独立 `WonderLab-test` 身份，不覆盖已有 WonderLab，也不接管课程文件关联。

目录已列出的地址，只有在维护者上传对应 Release 资源后才可访问；本文件或源码 tag 不证明资产已经上线。

## 支持与限制

- 机器人、积木、菜单、集中四语及 Python 规则采用同一个产品类；当前只支持 Python，不包含 C 或新的编程目标。
- `rgb-light`、`mp3`、`ultrasonic`、`line-8` 尚无公开主控支持项。它们包含在源码和发行集合内，但不能宣称在某个主控中即装可用，也不应自行扩大支持表。
- 旧课程中的部分舞台运动积木没有 Python 生成规则，例如 `motion_changexby`、`motion_changeyby`、`motion_goto`。工程可保存，不代表可完整生成并上传控制程序。
- 包内资源打包不等于设备 SDK 或固件部署；复杂视觉功能及真实硬件行为仍需对应设备验证。
- 原生产品类会执行作者代码，只安装可信来源的包。当前没有把外部扩展代码隔离为安全沙箱。

## 维护与回退

各产品 `catalog.json` 是发行历史唯一维护源，保存包版本、库版本、tag、资源名、地址及状态；根索引从其派生。新发行与归档 ZIP 的校验方式见[目录手册](../native-catalog.md#按产品维护-catalogjson)。正式根目前仍保留 v2 兼容格式，分层根激活另行确认。
不要手工修改包内库快照来匹配目录，不要覆盖已发行的同版本 ZIP；内容变化时升级相应包版本。
只改目录状态或为同一份 ZIP 增加正式下载地址，不需要机械提升所有包版本。

发生目录发布错误时，恢复根目录 JSON 的前一提交；不要删除用户工程已锁定的版本或移动已发布 tag。
撤回目录不等于卸载本机包，也不等于自动回退已确认升级的工程。
普通用户手写独立包仍直接检查、打包、导入，不需要加入官方发行历史。
