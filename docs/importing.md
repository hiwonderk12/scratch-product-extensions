# 导入与使用积木包

## 软件要求

普通用户拓展需要 WonderLab 桌面软件支持独立原生 class ZIP 导入和离线存储，不要求配套版本选择。
**目前未公布已通过这条教程全部桌面验收的最低发行版本号。** 请向软件提供者索取明确支持这些功能的版本；不要仅凭软件名称或版本较新推断兼容。
不支持该协议的旧版软件、WonderCode 软件分支或普通 Scratch 不能直接用本分支的包。

## 获取什么文件

从可信作者获取**积木包 ZIP**和配套说明；制作示例见[入门教程](getting-started.md)。官方产品由[根目录索引](../catalog.json)定位各产品的历史目录，历史目录记录对应 Release ZIP；仓库中的作者源码不代表每个历史版本。
GitHub 源码 Download ZIP、`src/index.ts`、单独的 JSON 和 `package-set.json` 都不是积木安装包。
独立用户 ZIP 包含 metadata.json、编译类入口和可选资源，不包含固定全库配置；安装会执行作者代码，只导入可信来源。

## 普通用户包：直接导入一次

1. 打开“用户拓展 → 导入本地库”，选择作者通过 `pack 作者目录` 生成的单个 ZIP。
2. 在“确认拓展包来源”中核对文件和拓展名称，仅在信任来源时点击 **信任来源并导入**。名称由作者填写，不是身份认证；类会在软件中执行，不受安全沙箱隔离。取消不会安装或执行这个包，也不会替换原包，可再次选择同一文件。
3. 成功后立即挂载类中的积木；无硬件默认适配无需先选主控。有明确主控限制的硬件包仍须选受支持的主控。
4. 检查分类、菜单及 Python，保存项目、退出后断网重开验证。本地磁盘保存包资源，项目不内嵌作者代码。
5. 再次导入同一模块会重新确认来源，确认后替换当前内容，只保留一份，不出现多版本或配套选择；其他项目窗口应关闭重开。

可信来源确认是软件开发版新增的本地原生包导入步骤，不是沙箱、签名验证或代码安全审计；CLI 检查通过也不代表作者代码安全。旧软件若没有此提示，仍需自行核实来源，本页不据此声明最低已验收发行版本。

不要导入包含多个 ZIP 的外层分发套件；请作者生成独立单包。目录格式和源码编译见[独立包格式](standalone-package.md)。

以下内容只适用于官方硬件库旧项目兼容与配套维护，**不是普通用户包的必做步骤**。

## 官方硬件库：导入配套包

以下入口名称对应中文界面；其他语言的文字会不同。先保存已有工作，首次使用请新建空白工程。

1. 打开积木区的拓展库，点击 **导入本地库**，选择作者提供的主控 ZIP。
2. 再次点击 **导入本地库**，选择模块 ZIP；如果有更多配套模块，分别导入。
3. 在 **主控扩展** 中点击对应主控的版本数字，在版本列表选中目标版本，再点击 **使用**；然后在 **模块扩展** 中以同样方式启用模块。官方包不在 **用户拓展** 中选版。导入成功只是安装成功，不等于已切换工程。
4. 若出现 **切换项目积木包版本**，核对主控、库配置和每个模块版本，明确选择同一配套后再确认。缺少候选就先补齐包，不选择其他不相关版本。
5. 回到积木区，检查分类、菜单、默认值及代码区的真实 Python。没有设备时不要上传。

本地导入官方格式的原生 ZIP 也要逐次确认可信来源；包内的官方元数据不能证明下载来源。取消不安装，不改变当前工程版本。本轮提示不覆盖远程目录下载、内置加载或已安装包的恢复，不应理解为这些路径已做来源认证。

官方配套参考见[维护教程](official-package-tutorial.md)。已有官方工程如果启用了别的模块，也必须提供那些模块的同配置版本；不要通过删除原工程积木来掩盖缺配套。

切换不同主控会要求确认清空积木；操作前请另存原工程，不要用切换主控代替同一产品的版本升级。

## 官方硬件库：版本更新、移除与离线

- 新版与旧版可以共存。升级或回退应明确点击目标版本，安装不等于升级。
- **检查版本**只读取目录并反馈成功或失败，不切换页面、不下载或升级当前工程。具体历史版本、详情和操作位于对应主控／模块卡片的版本下拉中；未安装版本须先下载，再明确点击 **使用**。
- 键盘使用版本下拉：聚焦版本数字，按向下键从列表首项打开，向上键从末项打开。列表中的方向键、Home／End 只移动焦点，不下载或切版；按 Enter／空格查看该项详情，再按 Tab 到可用操作，Shift＋Tab 返回列表。无需逐项 Tab 穿过所有历史。Esc 关闭并回到版本数字，Tab 离开浮层时不拦截外部控件焦点。此交互已补入软件开发版，真实桌面显示与滚动仍需复验，不据此承诺最低已验发行版本。
- 保留旧课程需要的配套 ZIP；修改内容必须递增包版本，同版本内容不能覆盖。
- 移除前确认包是否仍被工程使用。不要因清理旧卡片而删除旧课程需要的版本。
- `.sb3` 保存积木、素材、代码文档和版本锁，但**不内嵌所有已安装包**。换电脑时，准确复现需安装原锁定配套 ZIP；缺历史版本时，新开发版可按[兼容恢复规则](versions-and-projects.md#保存与恢复)尝试当前配套，不必逐一手动找旧版。替代提示出现后应核对 Python 并另存副本，不能把兼容打开当原版本已安装。
- 保存自己的 `.sb3` 后正常退出、断网重开，确认积木、输入、Python和固定版本恢复。Tab 自动恢复不是另存工程。

## 常见问题

| 现象 | 检查与处理 |
| --- | --- |
| 找不到上述入口或 ZIP 无法识别 | 核对适配软件及其版本；不要把源码 ZIP 导入 |
| 安装成功但找不到积木 | 官方包在主控／模块页的版本下拉中启用，核对主控是否配置支持；普通用户包应在导入后直接挂载，检查导入错误提示 |
| 库配置快照不同、缺少配套版本 | 新开发版恢复无锁／缺版旧教案时先自动选择已安装或内置的同快照配套；确实缺少时再获取作者提供的配套包，不改 ZIP 绕过检查 |
| 同版本内容不一致 | 请作者递增版本重新打包；不要覆盖或删除旧课程的依赖 |
| 离线缺版本 | 新开发版先尝试当前已选／内置的完整兼容配套并告知实际版本；不能覆盖旧积木时明确失败。必须准确复现原代码时安装原版本 ZIP，不联网追随 latest |
| 代码含未支持积木提示 | 保存原工程并反馈；检查/打包成功不等于软件支持完整生成和上传 |

反馈请附软件版本、主控、包版本、完整错误信息、复现步骤和不含个人信息的最小示例。
