# 包版本与项目恢复

普通用户拓展按模块仅保存一份当前内容，重新导入覆盖，项目不锁历史用户包版本；见[独立包合同](standalone-package.md)。下文的不可变版本、库快照与配套规则仅适用于官方产品库旧课程兼容，不作为用户包开发前置条件。

面向维护产品积木与课程的开发人员。原生ZIP直接携带编译类、元数据、资源和库配置快照，不转换回旧清单格式。

## 版本职责

| 字段 | 职责 |
| - | - |
| profile | 软件系列与本地资源隔离，例如wonderlab |
| moduleId | 稳定模块身份，例如input/light-sensor；不是菜单名称 |
| version | 模块发行版本；同一profile/moduleId/version的内容不可覆盖 |
| libraryVersion | 包携带的主控支持、端口和variant配置快照版本；由打包工具写入 |

修改积木声明、Python、译文、图片或配置快照后，应递增模块metadata.json中的version。即使积木opcode不变，包内容发生变化也不能复用已经安装过的版本身份。需要保留旧项目使用的ZIP，不把新文件覆盖到旧版本下载地址。

库配置变化也属于包内容变化。配套包必须携带相同完整快照，而不只是填写相同libraryVersion字符串。调整全库配置后，需要给配套包递增版本并重新打包；不要手工修改ZIP内的extension.json伪装原版本。

## 安装不等于升级项目

- 多个版本可以同时安装，用户拓展按具体版本显示卡片；当前作品只启用每模块的一个版本。
- 首次导入、且兼容当前主控的普通模块可以直接加入作品；已有模块再导入其他版本时只安装，不替换当前实现。
- 点击另一版本需要确认。界面列出明确候选包；缺少同配置配套包或存在多个配套候选时停止，不自动取latest。
- 配置快照变化时，需要一起切换当前已启用模块的配套版本，不能将新旧快照混用。
- 回退也通过已安装版本的卡片明确确认。切换失败保留原资源、运行注册、Python规则和项目版本锁。
- 删除只删除该版本。当前作品正在使用的资源须先移除，不能因删除旧卡片而误卸载另一活动版本。

配套集合存在歧义时，应明确选择完整候选集合后再升级；宿主的集合切换接口不会按版本排序猜测。远端发行集合管理不由当前单包pack命令代办。

## 保存与恢复

完整项目在project.json的meta.nativeExtensions附加原生版本锁，包含profile、主控身份、库配置版本和各活动原生模块的moduleId/version/variant/namespace。选中的原生主控即使没有放置积木，也记录其包版本。旧opcode、菜单value和用户输入不因版本或语言切换改变。

包含兼容恢复修复的软件开发版采用以下规则；较早软件仍可能在缺版本时显示 `NATIVE_VERSION_MISSING`，更新软件后才具备新行为。

- 带锁且所需版本齐全：自动恢复原版本，不要求先在卡片中手动逐一切换；只下载新版不会改变这类教案。
- 历史版本缺失、或未记录模块版本：尝试当前已选的完整兼容配套。未选择的模块使用相同配置快照的基线、内置或唯一已安装资源，不按版本大小猜 latest，不联网自动下载。
- 无锁旧项目：以该项目主控的当前选择为准，没有选择时优先内置主控，再按同一完整配置快照选择模块。缓存旧基线或其他工程的模块选版不匹配时，自动改选同快照内置或唯一已安装候选；不能凑齐或存在歧义仍明确失败，不默认激活更高调试版本。缺版兼容恢复采用相同配套规则，完整精确锁恢复不变。
- 兼容加载前必须覆盖项目的旧 opcode，保留 namespace 和一致完整配置快照；profile 错误、未知锁格式、真正缺少积木或配套不完整仍明确失败，不生成残缺程序。
- 替代成功后弹出四语说明，列出历史请求和实际版本，提醒 Python 可能变化。积木和输入不修改，原文件不自动覆盖；核对生成结果后另存副本，新保存的锁记录实际采用版本。

此兼容校验不证明不同 SDK 版本在硬件上的行为完全一致。若课程必须复现原始代码，应安装完整历史 ZIP 后重新打开原教案；不要用替代后的副本充当原版依赖已恢复的证据。仅旧清单或软件基础积木不属于原生包锁的管理范围。

## 离线与备份

浏览器保存v2多版本资源，迁移时保留原v1缓存。桌面优先读取userData中的独立原生资源文件，经preload专用接口同步浏览器缓存；不与旧清单共用数据文件。桌面写入失败、浏览器容量不足或多窗口状态冲突会报错，不应显示安装成功。

课程分发应同时保留所需各版本ZIP。当前远端Release资源是否齐全要单独确认，不能把GitHub源码仓库存在当作离线恢复或下载资产已发布的证明。发布前仍需课程、语言、界面和硬件验收。


## 原生远端安装

[官方目录与下载](native-catalog.md)由根产品索引与各产品版本历史组成。主控／模块页点击“检查版本”读取默认正式源，点击版本数字选择、下载或使用版本。下载复用本地导入的不可变多版本安装服务；只安装，不升级或执行当前作品。项目恢复采用上面的精确／兼容规则，不因目录出现新版而联网追随 latest。“目录设置”仅用于显式改源，普通检查无需填写地址。
