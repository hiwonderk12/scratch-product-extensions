# 产品积木包维护手册

本手册说明当前仓库已有源码格式与维护入口，面向有编程经验的维护人员。仓库尚无独立 `ext` CLI；不能用未来命令代替当前实际工作流。
新格式与工具启用后，应更新本手册及相关产品说明，并继续保持旧课程工程兼容。

## 作者目录

当前产品源码位于 `products/<package-id>/`。修改前查看目标 `config.json` 与已有代码，不按目录名猜测固件 API。

| 位置 | 当前维护内容 |
| - | - |
| `config.json` | 包 ID/版本、产品说明、分类、专用输入控件和生成配置 |
| `python/main.ts` | 当前积木声明、参数与 Python 生成规则 |
| `python/_menus/index.json` | 当前格式的菜单显示文字与实际值 |
| `python/_locales/` | 已提供语种的积木/菜单文案 |
| `python/_images/` | 分类图标、积木图标与产品卡片资源 |
| `docs/codegen-cases.json`（若存在） | 按 opcode 和参数分支冻结的模板生成用例 |
| `docs/README.md`（若存在） | 产品维护说明 |

包 ID、积木 opcode、完整序列化 block type 与参数名是兼容合同，不能作为普通文案重命名。
菜单区分显示文字和实际 value。维护译文或显示文字时保持 value 不变。

## 修改一块积木

1. 确认产品与固件 API、参数、端口和当前完整 block type；检查是否已有课程使用该块。
2. 在现有作者文件中修改声明与生成逻辑；同步受影响的分类、菜单和专用控件配置。
3. 补中文及包中受影响的已有译文，保持参数占位符一致。不要以复制中文到所有语言文件充当翻译。
4. 补模板分支用例，验证导入、初始化、表达式或命令；帽子/事件还需验证完整程序的定义和最终注册顺序。
5. 从课程工程中验证字段值、连接输入和代码结果；修文案不能改变菜单值或旧字段含义。

例如创建按端口读取的对象，应验证相同端口只初始化一次、不同端口互不覆盖；两个不同传感器同端口也不能使用同一变量名。
主控不同可能使用不同 SDK 和 `read()` / `read_value()`，不得仅替换类名就认定适配完成。

## 当前检查与打包入口

当前 npm 工作流位于配套编辑器仓库，需由维护人员先准备其依赖。在编辑器仓库终端执行下列命令，`<product-repository>` 替换为当前公开库路径：

```sh
npm run extension:check -- --id ainovab --repository <product-repository>
npm run extension:pack -- --id ainovab --repository <product-repository>
```

必须保留 npm 参数前的独立 `--`。这些命令会执行对应检查或生成本地产物，不会自动发布远端版本。
当前严格检查器仍要求全包多语言键、菜单键和生成用例。部分历史共享包尚未符合该检查器，失败时需要区分源码问题与旧格式门槛，不能跳过检查后标成通过。
工具退出码、错误文件及所测产品范围都应在 PR 中说明。未来中文兜底规则需与实际加载器/检查器一同启用，不能只删除语言文件。

## 版本、合并与发布

- 内容或包内资料变化时递增包版本，保持根 `version` 与 `asset.python.version` 一致，不覆盖同版本发行文件。
- 打包器生成 `dist` 和目标 catalog 条目；复核包 ID、版本、下载路径与状态，不手工复制其他产品的兼容配置。
- 课程人员提交变更并发起 PR，说明具体积木行为、参数/生成结果和验证范围；负责人审阅合并后再执行独立发布。
- `draft` 只表示目录里的草稿状态，不等于 Release 已提供下载。检查、打包、合并与发布分别完成。
- 不把原始源码 ZIP 当作可导入拓展包；用户导入当前工具生成的包文件。

## 文档与资料

产品手册写清源码职责、端口、参数、示例代码和兼容约束。公共 CLI/SDK/Skill 的规范在同一仓库维护，避免多个文档定义不同的参数含义。
执行过程、迁移来源证据、内部审阅和阶段验收由软件主项目保存，不进入公开 `docs` 或产品手册。
